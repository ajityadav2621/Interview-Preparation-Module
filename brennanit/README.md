# Brennan IT — AI Application Development Engineer Preparation Guide

This guide prepares you for the **AI Application Development Engineer** role in Brennan IT's **Foundry**. It is intentionally **concept-first**: it explains delivery flows, architecture fundamentals, required basics, and interview questions with practical answers. It does not include a codebase or implementation repository.

## Role at a Glance

| Area | Details |
|---|---|
| Position | AI Application Development Engineer |
| Team | Foundry |
| Location | Mumbai |
| People leader | Foundry Lead |
| Core delivery model | Approved specification → AI-assisted build → peer review → testing → release |
| Primary outputs | AI-assisted applications, Beacon modules, Cowork skills, reusable components, integrations |
| Engineering priorities | Reliability, security, maintainability, reuse, auditability, measurable business outcomes |

## Interview Structure

| Round | What is assessed | How to prepare |
|---|---|---|
| Technical screen | Web development, REST APIs, databases, basic algorithms | Explain fundamentals clearly and reason aloud |
| System design | AI application architecture, scalability, security, integrations | Use the structured design framework in this guide |
| Coding discussion | Problem-solving, data structures, clean design | Explain approach, trade-offs, complexity, and edge cases |
| Domain knowledge | RAG, agents, MCP, CI/CD, containers, observability | Connect concepts to production applications |
| Cultural fit | Collaboration, documentation, governance, enablement | Use specific examples from previous work |

## Recommended Study Order

1. Read the role and Foundry pipeline.
2. Learn the standard architecture and request flows.
3. Study AI application fundamentals, especially RAG and evaluation.
4. Review integration, security, and DevOps fundamentals.
5. Practise explaining system designs aloud.
6. Practise coding discussions without jumping straight to syntax.
7. Run mock interviews using the question-and-answer files.

## Universal Answer Framework

For technical questions, use this sequence:

1. **Clarify** — confirm users, scale, data sensitivity, latency, availability, and constraints.
2. **Define the flow** — describe the end-to-end request or delivery lifecycle.
3. **Identify components** — explain boundaries and responsibilities.
4. **Address non-functional requirements** — security, reliability, scalability, observability, and cost.
5. **Discuss trade-offs** — explain why one design fits the situation.
6. **Close with risks** — name the main failure modes and how you would monitor or mitigate them.

For behavioral questions, use **Situation → Action → Result → Learning**.
